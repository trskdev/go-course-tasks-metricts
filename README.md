# Задачи: метрики, дашборды и трейсинг

Представь, что твой сервис в проде начал тормозить. Что ты делаешь? Идёшь в логи? Там миллион строк. Идёшь к коллегам? Они заняты.

Взрослые команды в такой момент открывают **три окна**:
- **Grafana** - "как часто и как быстро отвечает сервис прямо сейчас"
- **Prometheus** - "а что было 20 минут назад"
- **Jaeger** - "на каком именно запросе он тормозит"

В этих задачах ты развернёшь всё это локально и научишься думать как SRE.

> **Теория** - в курсе: [`05-infrastructure/5.4-observability`](https://github.com/Go-Courses-Tasks/go-course). Здесь - практика.

## Быстрый старт

Одна команда - и у тебя локально есть продакшн-уровневый observability-стек:

```bash
docker compose up -d
```

Проверь, что всё живо:
```bash
curl -s localhost:9090/-/ready       # Prometheus: "Prometheus Server is Ready."
curl -s localhost:3000/api/health    # Grafana:    {"database":"ok",...}
open http://localhost:16686          # Jaeger UI откроется в браузере
```

Куда смотреть:
- **Prometheus** - http://localhost:9090 (хранилище метрик + простой UI для PromQL)
- **Grafana** - http://localhost:3000, логин `admin`, пароль `admin` (красивые графики)
- **Jaeger** - http://localhost:16686 (трейсы)

Остановить:
```bash
docker compose down          # контейнеры остаются с данными
docker compose down -v       # стереть всё, начать с чистого листа
```

## Как это всё связано

```
┌──────────────────┐    GET /metrics    ┌──────────────┐
│  твой Go-сервис  │ ◀───────────────── │  Prometheus  │
│  :8081/metrics   │                    │    :9090     │
│  :8081/hello     │                    └──────┬───────┘
│                  │    трейсы по OTLP         │ PromQL
│  OTel SDK ───────┼──▶ :4318 ──▶ Jaeger       ▼
└──────────────────┘                    ┌──────────────┐
                                        │   Grafana    │
                                        │    :3000     │
                                        └──────────────┘
```

Разберём по ролям - кто что делает и зачем:

- **Твой сервис** раз в пару миллисекунд обновляет счётчики и гистограммы в памяти (Counter++ на каждый запрос). И отдаёт их текстом на `/metrics`.
- **Prometheus** раз в 5 секунд ходит на `/metrics` ("скрейпит"), складывает всё в свою time-series базу. На графиках ты потом смотришь уже его данные, а не сервиса.
- **Jaeger** принимает трейсы. Это отдельная история - не метрики, а "как прошёл КОНКРЕТНЫЙ запрос".
- **Grafana** не хранит ничего. Она просто умеет дёргать Prometheus и Jaeger и рисовать это красиво.

Конфиги, чтобы всё сразу работало (datasource-ы в Grafana, scrape-таргеты в Prometheus), лежат в [`infra/`](./infra/). Открой, посмотри - там всё с комментариями.

## Шпаргалка

```bash
# посмотреть сырые метрики - то, что Prometheus видит
curl -s localhost:8081/metrics | grep -v '^#' | head

# PromQL из CLI - когда лень открывать браузер
curl -s 'localhost:9090/api/v1/query?query=up' | jq

# нагрузочный тест: 30 секунд, 10 параллельных клиентов
hey -z 30s -c 10 http://localhost:8081/hello

# логи конкретного сервиса стека
docker compose logs -f prometheus
```
